# 自动放刀 v1.5（发布版）规格

第 1 轮标定已通过（报告：`tools/out/round1_report.md`，结论已写进 `docs/NOTES.md`「抵消上捞斩」一节）。v1.5 是在 rc（`AutoParryGS.lua` 1.5-rc1）基础上**做减法**得到的发布版：规则不变，参数冻结，删掉只为标定服务的部分。第 2 轮验收就验收这份代码。

用户已确认：默认提前量 **26 帧**；先做精简版再验收。

## 1. 冻结的参数

| 参数 | 值 | 依据 |
|---|---|---|
| `parry_lead`（L，菜单滑块） | 默认 **26**，范围 **22~45** | C3 满覆盖平台 26~33；取下沿，让碰撞尽量早于上捞斩自己先砍中怪物（第 1 轮 8 次「空放」里 6 次是先砍中把怪物打出硬直/倒地/麻痹） |
| `LEAD_MIN`（L_min） | **22** | C4：⌈60·(W0+0.02+δ−Q25(r))⌉ |
| `LONG_WINDOW`（W_long） | 60 | C5：(30,60] 组接住 10/10 |
| `VETO_HORIZON`（H_veto） | 90 | 固定 |
| `CREDIT` | 1.3 s | 接住判定 |
| `TRACK_MAX` / `TRACK_STALE` | 32 / 8.0 s | 不变 |

## 2. 保留（从 rc 原样或精简保留，行为不变）

- 预告消息钩子 + `add_ref` 跟踪，释放条件与淘汰口径不变（CONTRACT 3.3）。
- 每帧 pre-UpdateBehavior 求值：前提 P1~P3、逐条 DANGER、否决 V、候选过滤（`hs ≥ L_min`、`0 ≤ he−hs ≤ W_long`、ShellIndex 无值（三种 Nullable 形态都认）、DamageType ∉ {EAR, WIND, QUAKE}，读取失败按通过并计 `failopen`）、`Q* = min hs ≤ L` 就请求 (2,23)、streak 合并、不设超时。
- 唯一有副作用的调用仍是 `changeActionRequest(LAYER 0, (2,23), false)`。
- 结局统计：FIRE / FIRE_END / RES（CREDIT 内进 (2,25..27) 记 CATCH）/ VETO / STAT / ERR / RED，`emit` 写日志 + JSON 分块（`AutoParryGS_<session>_<seq>.json`，写出时机不变）。第 2 轮验收的离线分析靠这些记录。
- 错误分级：核心（msg、frame、fire、json）10 s 内 3 次标红；帧逻辑连续 30 帧出错自停并释放全部引用；读主角瞬时抛错 1.5 s 内容忍。
  - 澄清：自停和 Reset 时还在等结局的那一刀当场记 `RES NOCATCH`（每个 FIRE 都有一行 RES，口径同主角消失时）；自停后不再读主角，空闲写出 JSON 不再看主角动作（否则停在最后读到的 (2,21)~(2,29) 就再也不自动写出）。
  - 澄清：Reset 收尾的顺序是先释放引用、结算 streak 和 RES、补写 STAT、写最后一份 JSON，最后才把排队的 ERR 一次写完；最后一份 JSON 写失败的那条 ERR 不受日志 20 行上限限制（之后再也写不出 JSON，只剩日志）。
- 配置读写与类型校验；`re.on_script_reset`、关开关、主角变化时全部释放。

## 3. 删除

- L 轮换（`ROTATION`、`lead_rotation` 配置项）。
- 机关扫描（`scan` 配置项、全部 SCAN 逻辑、扫描用的受击钩子）。
- closest 兜底（`src=FB`）：第 1 轮 34 次放刀兜底 0 次、自检2 全过。改为：某个结果逐条读取出错 → 这个结果本帧不参与（不放刀），计 `readerr`，第一次出错标黄（可选模块 `items`）。
  - 澄清：「不参与」= 既不进候选 C，也不参与否决 V（条目读不出来，就看不到它有没有长窗口条目）。和 rc 不同：rc 退回 closest，closest 那条是长窗口时会否决。读出错时要不要改成保守口径（整体 DANGER 就整帧否决）是规则改动，由用户决定。
  - 澄清：`items` 报黄但不停用逐条读取（停用就再也放不了刀），之后照样每帧重读。菜单状态行写「条目读取出过错（读取错误 n）：读不出条目的预告不放刀」，不套「有可选模块停用，自动放刀照常」（那句只用于读失败按通过的过滤器 `shell`/`dmgtype`/`master` 和 `cfg`/`ui`）。
- HUD（`draw.text` / 浮动窗口）：发布版只在 REF 菜单里显示状态；第 2 轮验收期间屏幕提示由探针负责。
  - 澄清：探针只能提示它自己的状态，看不到放刀模块（两个脚本互不可见）。放刀模块标红或自停只显示在 REF 菜单「自动放刀（实验）」的状态行里；第 2 轮的操作说明要写上：每打完一只怪、或觉得不再自动放刀时，打开菜单看一眼状态行，变红就停下发日志。
- DBG 行（`debug_log` 打开时只保留关键事件的调试日志，可以继续用 `dbg`，但不许每帧刷）。

## 4. 新增

1. **联机副本闸门**：收到预告消息时，用 `msg:call("get_SendGameObject")` → `getComponent(app.EnemyCharacter)` → `enemy:get_field("_Context"):call("get_IsMaster")` 读一次并存进跟踪记录。为 false（本机不是这只怪的主机，怪物是副本）时，这个结果的条目**不进候选**，计 `replica`。读取失败按「是主机」处理（fail-open），计 `failopen`。第 1 轮实测这条链 100% 可读（单人时恒为 true）。
2. **CFG 记录**：启用开关或提前量滑块每次改动写一行 `CFG t auto_parry lead`（总写日志和 JSON，不受 debug_log 控制）。第 2 轮验收只用第一次改动之前的数据（PLAN D）。
   - 澄清（PLAN D 说的是滑块改动）：截断点是第一次**提前量**改动；只切启用开关不截断（开关不改规则参数），验收只去掉开关关着的时段。滑块改动会存进配置，所以之后加载的 session、以及加载时提前量就不是 26 的 session 整段不算（分析脚本 1.2 起按此执行）。「调试日志」开关和「清零统计」不写 CFG。
3. HDR 保持原字段，`ver=1.5`、`rotation=0`、`scan=0`，方便分析脚本复用。

### 4.1 记录格式和 CONTRACT 的差异（澄清）

CONTRACT 第 3 节写的是 rc 的口径。v1.5 的记录在 CONTRACT 3.4 的基础上（只是本节第 1~3 条落到记录上的写法）：

| KIND | v1.5 |
|---|---|
| `HDR` | 字段同 rc；`ver=1.5`，`rotation`、`scan` 恒为 0，`L_min=22` |
| `FIRE` | 字段同 rc；`L` 是当时的滑块值，`src` 恒为 `V0`（没有 FB） |
| `VETO` | 字段同 rc；v1.5.1 在原字段后追加 `why=long\|grab`（长窗口 / 抓取，取触发 hs 最小的那条，同 hs 记 `long`；见第 9 节第 2 条） |
| `STAT` | rc 的 12 个字段（`fb` 恒为 0）之后追加 `replica`（登记时判为联机副本的预告结果数）、`readerr`（出过逐条读取错误的预告结果数，每个结果计一次） |
| `CFG` | 新增：`t auto_parry lead`，见本节第 2 条 |
| `SCAN` | 没有（只有 rc1 写） |

CONTRACT 1.2 末句「rc 的条目逐条读取失败时退回 `getClosestDetectedData()`」只适用于 rc1；v1.5 按本文第 3 节。配置见本文第 5 节、菜单见第 6 节（CONTRACT 3.1、3.6 是 rc 的）。

## 9. v1.5.1（第 2 轮验收中途发现问题后的修订）

第 2 轮验收在新怪 em27（Em0160）上打了 9 刀（数据存档 `tools/out/round2a_data`，session 1791658621）：接住 6，**放早 2**（同一招 (0,82)，两次都比预告早到约 0.11~0.12 s，r ≈ −0.12，接触在 0.31 s 落在 W0 之前），**被抓 1**（伤害类型 `CATCH`、防御类型 `SKILL_GUARD`，刀碰到了但抵消不触发，吃了 259 伤害）。用户同意中止验收、先出 v1.5.1：

1. **提前量默认值改回预注册的 30**（C3 平台 26~33 的中点，PLAN 原规则）。改成 26 是看了第 1 轮数据后的偏离（为了少一些「先砍中打断」），新怪数据显示它压缩了早侧余量：L=30 时上面两次接触约在 0.38 s，落在窗口内。滑块范围仍是 22~45，`LEAD_MIN` 仍是 22。
   - 配置升级：配置文件里**没有 `cfg_ver` 键**（rc 或 v1.5 写的）→ `parry_lead` 一律改成 30（26、28 都不是用户自己调的值），写一行 DBG `cfg_upgrade`；v1.5.1 存配置时写 `cfg_ver = 2`，之后用户自己调的值原样保留。
   - 澄清：只在读到了配置文件、且里面没有 `cfg_ver` 时升级（没有配置文件就是默认 30，不算升级）；「一律」= 不看原值是多少（35 也换成 30）。DBG `cfg_upgrade` 和其他调试行一样只在「调试日志」开着时写，`from` 记文件里的原值；HDR 的 `lead` 是升级之后的值。
   - 澄清（第 1 轮审查后）：存档 session 1791658621 一共 12 刀（FIRE 12 行；离线分类 CATCH 8、FAIL_EARLY 3、FAIL_OTHER 1，见 `tools/out/round2a_report.md`；另有长窗口 VETO 2 行）。开头的「9 刀」是前 9 刀（id 1~9）。第 12 刀是 (0,78)：R0=25.14，首个接触 c_first=0.184 s，是第三次放早；L=30 只能推到约 0.25 s，仍早于 W0=0.328，要 L≥35 才越过 W0。所以本条「L=30 修正放早」的依据只覆盖 (0,82) 那两次，(0,78) 这次 L=30 修不了；这会不会影响取 30，由用户决定。
2. **抓取否决**：`DamageType` ∈ {`CATCH`, `CATCH_ZAKO`, `CATCH_SLINGER`}（按名字从 `app.HitDef.DAMAGE_TYPE` 读，读不到的名字跳过）的条目是抓取，抓取无法抵消：
   - 抓取条目永远不进候选 C；
   - 存在 DANGER 的抓取条目且 `hs ≤ H_veto`、`he ≥ 0`（即将到来或正在进行）→ 本帧否决，和长窗口否决同一口径（同一个否决 streak 只写一行 VETO）。
   - VETO 记录在原字段后追加 `why=long|grab`（多个原因时取触发 hs 最小的那条）。
   - DamageType 读取失败按「不是抓取」处理（fail-open，计 `failopen`，口径同 EAR/WIND/QUAKE 过滤）。
   - 澄清：三个名字 2026-10-11 用 MCP `get_type` 核对过都在 `app.HitDef.DAMAGE_TYPE` 里（数值 get_type 不给，脚本按名字读，不依赖数值）。名字读不到时跳过、不标黄、不停用伤害类型读取（EAR/WIND/QUAKE 过滤和其余抓取照常），加载时总写一行 `DBG ev=grab_enum skipped=<名字>`（不受调试日志开关控制，同 self_stop），免得游戏更新改名后悄悄少认一种抓取。
   - 澄清（第 1 轮审查后）：反过来也一样，EAR/WIND/QUAKE 的名字也逐个读，读不到不能连带停掉抓取否决。读不到的效果名字标黄一次（ERR `mod=effect_enum`，菜单「有可选模块停用，自动放刀照常」，和 `shell`/`dmgtype`/`master` 同一类），但不停用伤害类型读取：抓取否决、读到的效果类型照常（以前三个名字一起读，缺一个就记成 `dmgtype` 停用读取，抓取否决也跟着没了）。这时认不出的伤害类型可能就是没读到的那种效果攻击，按读不到处理：通过（fail-open），每个条目计一次 `failopen`（口径同 v1.5 枚举读失败：v1.5 是整个伤害类型读取停用、每个条目计一次）；认得出的抓取和效果类型不计。
   - 澄清（第 1 轮审查后）：不放刀不等于不被抓。第 2 轮那次抓取（session 1791658621，39339.465 身体接触）探针 CT 的 `sa=1`、ARM 从 39338.427 到 39340.253 没有变化，SUPER_ARMOR 一直开着，照样从 (2,23) 进了 (0,414) cDamageCatchBossSlip → (0,416) cDamageCatchBoss；蓄力中的霸体挡不挡得住抓取没验证过。抓取否决的作用只是不把人锁进 (2,23)、不白放一刀（未验证）；代价是抓取在 1.5 s 内到来时整帧否决，会连带压掉别的怪能抵消的攻击。值不值得，第 2 轮数据出来后看「被抓取规则否决」的漏报和被抓取否决之后的结局复核，由用户决定。
   - 澄清：伤害类型要对 1.5 s 内到来或进行中的 DANGER 条目（`hs ≤ H_veto`、`he ≥ 0`，候选都在里面）都读，不只是候选，所以读不到时 `failopen` 也按这些条目计（每个条目一次）；弹体仍只对候选读。副本（`get_IsMaster=false`）的抓取条目照样否决，口径同长窗口。
   - 澄清：同一帧里长窗口和抓取触发否决的 hs 一样时，`why` 记 `long`（v1.5 就有的规则优先）。
